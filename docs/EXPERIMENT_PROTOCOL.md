# Experiment and timing protocol

This document defines the reproducible protocol introduced for the research
improvement plan. It covers the classical pilot, complete multi-seed study,
controlled ablations, generated manuscript evidence, and verified PDF build.

## Clean-checkout commands

Install the dependencies in `requirements.txt`. The short classical pilot is:

```bash
python scripts/reproduce_classical.py
```

The command runs the unit tests, regenerates the stable scenario manifest,
executes Dijkstra and A* on every identical scenario for 10 repetitions, and
regenerates the summary table.

Use `--repetitions N` to change the timing repetitions. Values below two are
rejected because they cannot support a standard-deviation estimate.

The complete study, including five-seed training for every configured method
and ablation, is one command:

```bash
python scripts/run_full_research.py --train
```

The pipeline is checkpointed and intentionally long. Subsequent artifact
replication omits `--train`. The final stage installs a checksum-pinned local
Tectonic release when necessary, rejects incomplete evidence, compiles the
paper, and writes a PDF build manifest.

| Artifact | Role |

## Matching rules

Dijkstra, A*, D* Lite, and RL use the same movement graph, costs, scenario IDs,
obstacle schedule, maximum steps, and information timing. Each action is
selected from the currently observed state and executed first. Dynamics then
advance; the resulting changed state is included in the observation or graph
available before the next action is selected. A terminal move does not generate
an event that no method can observe or react to. No method reads future toggle
times. This `post_move_observed` contract prevents a policy from being judged
on a hidden change while a classical planner is allowed to react to it.

## Timing definition

`time.perf_counter()` wraps each planner call. Route-level compute time is the
sum of all planner calls made from the initial plan through arrival or failure.
This excludes environment construction and CSV/JSON serialization.

The raw CSV retains every timing repetition and each replan event. The summary
reports count, mean, median, sample standard deviation, and a normal 95%
confidence-interval half-width. Per-decision latency is reported as the median
planner-call duration for each route.

Timing results should not be compared across machines without consulting the
associated environment manifest.

## Adaptability definitions

For each observed obstacle change, the evaluator records:

- **Optimal-cost shock:** the new optimal remaining path cost minus the optimal
  remaining cost immediately before the change.
- **Positive extra optimal cost:** the non-negative part of optimal-cost shock,
  measuring the extra optimal remaining cost attributable to the event.
- **Recovery steps:** movement decisions after the change until the current
  optimal remaining cost is no greater than its pre-change value.
- **Route disruption:** an unrecovered event at episode termination is retained
  as missing recovery time rather than silently discarded.
- **Post-change success:** whether the complete route eventually reaches its
  goal after that event.
- **Reaction work:** planner time and node expansions for classical methods, or
  policy decision latency for RL.

The definitions use only state visible when a change occurs and make no use of
future obstacle schedules.

## Reproducibility boundary

Research checkpoints are intentionally excluded from version control because
of their size. They are regenerated by the checkpointed local runner, and the
expanded evaluator refuses legacy or smoke-test models. Raw result rows retain
stable run IDs and the benchmark-manifest digest. The release PDF is generated
only after row-count, uniqueness, and manifest-integrity checks pass.

## RL reward-shaping rule

New research runs use normalized octile distance as the potential function.
Octile distance matches the project's straight and diagonal movement geometry,
but does not depend on the obstacle state at replay-sampling time. This makes
potential-based shaping compatible with HER in a dynamic environment.

The earlier shortest-path-distance potential is retained only as an optional
static-environment experiment. It is rejected for dynamic HER training because
HER may relabel transitions collected under different obstacle states; using
the environment's current grid to recompute those rewards is not valid.

## Expanded suite

`evaluation/manifests/benchmark_v2.json` is the single source of scenario
identity for the expanded study. It separates held-out endpoint pairs, unseen
layouts, denser layouts, new dynamic locations, changed toggle periods, grid
scales, density sweeps, stochastic and moving obstacles, wind/energy maps,
hard and penalized no-fly zones, and sensor-noise conditions.

The full baseline-only pipeline is:

```bash
python scripts/run_full_research.py --train --variants full
```

Omitting `--variants` runs the full method and all six ablations. Training is
optional on subsequent replication passes because it is checkpointed and
long-running. Omitting `--train` never silently substitutes the legacy seed-42
model; missing research checkpoints cause a hard failure.
